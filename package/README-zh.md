# YinHuGuard 首次运行说明

## 这是什么

一个**只读**的排查工具，用来把「银狐」木马常见的隐藏进程、启动痕迹与落点列出来。

它一共查**七个面**。前三个来自一份流传较广的批处理脚本（原作者 B 站
@SYSTEM-RAMOS-ZDY）的三段扫描：

1. **隐藏进程** —— 找出可执行文件带「隐藏」或「系统」属性的进程
2. **隐藏启动项** —— 找出三个 Run 注册表键里指向隐藏文件的项
3. **可疑服务** —— 找出以命令行解释器启动、或程序不在系统目录下的服务

后四个是这个工具自己加的深扫面，每一个都有厂商报告佐证：

4. **注册表载荷** —— `HKCU\Console\` 下以 32 位十六进制命名的值、`IpDates_sun`、
   `Magisk`，以及 `FaCai2024` 标记串。**这类东西不是启动项**，但只删启动项不删
   载荷，重启就回来了
5. **驱动服务** —— 已知的 BYOVD 驱动名，以及 `ImagePath` 不在 `System32\drivers`
   的驱动。银狐用它把杀不掉的进程送进内核结束掉；这些驱动**全都有合法签名**，
   所以只能按已知文件名认
6. **文件落点** —— 已知的完整路径清单、`ProgramData` 下的任意 `.sys`、IE 目录下
   恰好 6 位字母数字的随机子目录
7. **计划任务** —— 已知任务名，以及 action 指向非常规目录的任务

七个面是**依次跑完**的，不能只挑一个跑。深扫那四个比较慢，整个扫描从秒级
变成**分钟级**，其中计划任务最慢。

## 它不做什么

**这个工具不会修改你的系统。** 它不删文件、不改注册表、不动服务、不结束进程。
它只是读取并汇报。

原作者那份「解禁杀毒软件」脚本会做破坏性操作（删 hosts、删 WDAC 策略、写 IFEO 劫持、
禁用全部计划任务），**本工具不包含那些功能**。那些操作里有几处会伤到系统本身，
例如它会把 Windows 的卷影复制服务当成银狐驱动删掉。

## 怎么运行

1. 把整个压缩包解压到一个文件夹（**不要**在压缩包里直接双击）
2. 双击 `YinHuGuard.exe`
3. 点「开始扫描」

程序**打开时不会自动扫描**。这是有意的：一个安全工具在你还什么都没点的时候
就去枚举全机进程与服务，是最容易被当成恶意软件的行为。

扫描结束后，日志和报告写在**程序旁边的 `reports` 目录**里；如果那个位置不可写
（比如装在 `Program Files` 下），会退到「我的文档\YinHuGuard」。

也可以命令行用：

```
YinHuGuard.exe --scan                     扫描并打印摘要
YinHuGuard.exe --json D:\report.json      扫描并把 JSON 报告写到指定位置
```

退出码：`0` 没有命中，`10` 有命中，`1` 参数错误，`2` 引擎错误，`3` 找不到配置文件。

## 首次运行被 Windows 拦住了

本工具**没有做代码签名**。个人开发者的代码签名证书需要每年约 200 美元，
一期没有购买，所以 Windows SmartScreen 会提示来源不明。这是预期行为。

处理方式：

1. 看到蓝色的「Windows 已保护你的电脑」窗口
2. 点**「更多信息」**
3. 点**「仍要运行」**

如果这个窗口让你不舒服，那是合理的——一个查杀木马的工具本身就值得怀疑。
你可以先只运行命令行模式（`--scan`），它会生成一份报告，而不是直接操作界面。

## 怎么读结果 —— 这一节最重要

### 「没有命中」不等于「机器干净」

这是使用这个工具最容易犯的错，也是它界面上反复强调这一点的原因。

普通权限下，**Session 0 的进程路径几乎全都读不到**（Windows 的权限设计如此；
实测能读到的通常只有个位数）。Session 0 是所有系统服务和后台进程所在的地方，
也正是银狐这类木马最常藏身的地方。所以不点提权的话，「扫描完成，没有命中」的
真实含义是**「这一部分没有被检查过」**。

界面上的「本次扫描的覆盖范围」这一块就是为此存在的。它会给出四种状态之一：

| 状态 | 界面 | 含义 | 你该做什么 |
|---|---|---|---|
| **不完整** | 红色块 | 有东西因为**权限**没查到，提权能解决 | 点右上角「完整扫描（提权重跑）」，UAC 选「是」 |
| **已提权：能检查的都已检查** | 蓝色块 | 已提权、权限层面没有缺口；仍有少数条目读不到（系统保护进程如 csrss.exe、扫描瞬间退出、数据不可读）——列表里逐条标着「未覆盖」，属正常现象 | 不用做什么，可以按结果下结论 |
| **覆盖完整** | 蓝色块 | 已提权，且列表里没有任何「未覆盖」条目（真机上少见） | 可以按结果下结论了 |
| **自检异常** | 红色块 | 连进程/服务都没枚举到，引擎没正常工作，本次结果不可用 | 重新扫描；反复出现就重新解压一份完整的包 |

请特别注意自检面板里的这几个数字：

- **管理员权限：否** —— 说明没提权
- **Session 0 可见进程：接近 0** —— 说明系统进程基本都没看到

只要面板上还写着「因权限未检查」的条目，界面就会显示红色警告。
**请务必以管理员身份重新扫描一次**，再根据结果下结论。

**为什么「有残留」不算红色警告：** 如果算进去，这块面板就永远是红的——扫描那一刻
总有进程在退出。一个永远关不掉的警告等于没有警告，看两周你就会开始无视它，
那反而是最危险的。但残留会阻止蓝色「覆盖完整」——列表里还有「未覆盖」条目时
不能自称完整；这就是真机上更常见「已提权：能检查的都已检查」的原因。

### 报告里的标记

- `未覆盖` —— 这一项没被检查（权限不够、系统保护或数据不可读），**不是**「检查过没问题」；每行下方写明具体原因
- `需要提权` —— 未提权时出现：这一项提权重跑就能覆盖
- `系统保护` —— 已提权时出现：连管理员也读不到（如 csrss.exe 这类系统进程），属正常残留；若对象不是已知系统进程，请人工核实
- `已按白名单折叠` —— 命中了白名单，收在下面但不隐藏，你可以回头看自己白掉了什么
- `隐藏属性` / `系统属性` —— 命中原因（文件属性）

## 报告可以发给人看

JSON 与 CSV 报告会自动把**你的用户名和机器名**替换成 `<USER>` 与 `<MACHINE>`，
**文件路径保持原样**。路径保留是有意的——帮你远程看报告的人需要知道文件到底在哪，
否则他无法判断该不该动手。

## 它可能报错（误报）

这个工具用的是「隐藏属性」「不在系统目录」这类启发式判据，**必然存在误报**。
几种常见情况：

- 有些正常软件会把自己的文件设成隐藏
- 某些厂商的驱动、安全软件的服务路径本来就不在 `System32` 下
- 你自己隐藏过的文件
- 深扫那四个面按「已知名单 + 位置异常」判，名单之外的变种一律查不到

所以：**它列出来的东西需要人确认，不能直接照着删。**

如果要减少噪音，可以编辑程序旁边的 `rules.json`，在 `process_allowlist` 里加上
你觉得正常的东西。这个文件是纯数据，改坏了程序会拒绝启动并告诉你哪个键不对。

> 深扫面用的威胁名单**不在** `rules.json` 里，而是编译进引擎的。原因：那不是
> 给用户调的旋钮，而是从厂商报告正文逐个抄来的事实，每一条都带出处。放进配置文件
> 等于给人「随手删一条就不会再报」的自由度。

## 它读什么、不读什么

程序**不联网**，没有任何上传、没有崩溃上报、没有自动更新。
`rules.json` 就在程序旁边，你可以自己看里面判定用的是什么。

有几种手法**故意没有收录**，因为它们找不到银狐实际使用的公开证据，收进来只是噪音：

- Winlogon 劫持（`Shell` / `Userinit`）、IFEO 映像劫持、WMI 事件订阅
- COM / TypeLib 劫持、DLL 侧载、企业管控软件寄生
- 进程代码签名校验（银狐专门注入 `svchost` / `winlogon` / `explorer`，签名校验是
  对这类「进程名看起来正常」的唯一可靠解，但仍在做）

## 一个诚实的说明

本工具覆盖的是银狐**已知手法**里的一部分。七个面都查完了，也不代表把银狐所有
变种都堵住了——它的落点名单在持续变化，判定也仍是启发式。

也就是说：**它说没问题，不代表真的没问题。** 它只是一个辅助手段。

如果怀疑机器确实中招了，正确处理顺序是：

1. 用这个工具看有没有明显痕迹（记得提权跑一次）
2. 装一个正规杀毒软件（火绒、360 均可）做全盘扫描
3. 杀毒软件也打不开的话，说明机器被劫持得比较深，考虑重装系统
